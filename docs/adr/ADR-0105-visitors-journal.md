## Quality Axes

- **Ambition target**: **R2** — власник бачить живих людей на платформі: хто прийшов уперше, хто повертається, скільки

- **Maturity impact**: **M2 → M3** — замість ручного розбору логів nginx (IP змінюються, кеш ховає повторні візити, атаки

## 1. Контекст

Власник 29.09: «хочу мати розуміння, що ми комусь потрібні»; бачити реальних відвідувачів, базово розрізняти людину,
що періодично приходить (як довго з нами), і бачити ботів та атаки — «але не спам» (попередня спроба «маячила постійно
про ботів»).

Ретроспектива 14 днів логів nginx (15–29.09): «браузерів», що завантажили графік, 0–7 на добу (31 різний), повторних 4 —
але метод ненадійний: IP однієї людини змінюється (мобільний, VPN), кілька людей бувають за однією адресою, повторний
візит береться з кешу браузера й у лог не потрапляє. WS-сервер бачить кожне підключення як 127.0.0.1 (у лог пише
`request.remote`). Атаки (`wp-login`, `.env`, `.php`) nginx навмисно не пише (`access_log off`) — їх не видно зовсім.

## 2. Розглянуті варіанти

| # | Варіант | Чому ні / так |
|---|---|---|
| A | Лише логи nginx (IP + User-Agent) | Ненадійна ідентичність, кеш ховає повторні візити, боти з підробленим UA (Tencent «iPhone») |
| B | Стороння аналітика (GA, Plausible SaaS) | Дані третій стороні, скрипти на графіку, банери згоди; не бачить WS-сесій і тривалості |
| C | Ключ у `localStorage` браузера → параметр `vid` WS-адреси | Потребує зміни UI; ключ у URL лягає в лог nginx поруч з IP; Safari стирає сховище скриптів через 7 діб без взаємодії |
| D | **Першосортний сигнал застосунку: ключ у HttpOnly-cookie на `/ws`, який видає WS-сервер + журнал WS-сесій на нашому сервері; боти/атаки — зведенням з логів nginx** | **Обрано**: точна тривалість (WS), повторні візити незалежно від IP/кешу, UI не змінюється, ключ не в URL і не в JS, нуль сторонніх, нуль персональних даних |

## 3. Рішення

### 3.1 Ключ відвідувача
WS-сервер у відповіді рукостискання `/ws` видає cookie `aione_vid` — випадкові 32 hex-символи (`uuid4`), `Path=/ws`,
`HttpOnly`, `SameSite=Strict`, `Max-Age` рік, `Secure` коли сторінка відкрита по https (заголовок `Origin`). Прийшов з
валідним ключем — той самий ключ, строк продовжується (людина, що періодично повертається, лишається собою); без ключа
або з невалідним — новий. Лише випадковий рядок — ні імені, ні пошти, ні «відбитка» пристрою. Браузер не зберігає
cookie (заборонені, приватне вікно) або бот без cookie-сховища — кожен візит виглядає новим; зведення показує це як
«новий», без обходів. UI не змінюється.

### 3.2 Журнал візитів
Одна WS-сесія = один рядок JSONL у `visitors.dir/sessions-YYYYMM.jsonl` (місяць — за початком візиту, UTC): `vid`,
`vid_issued` (ключ видано в цій сесії), початок, кінець, тривалість, країна (заголовок Cloudflare `CF-IPCountry`; `XX`/Tor
→ null), клас пристрою з User-Agent (ОС, браузер, мобільний; сирий UA не пишеться), ознака бот-UA, `internal` (нема
`X-Real-IP`, який nginx ставить кожному зовнішньому `/ws`: підключення з самого сервера — службові зонди), `home_net`
(адреса з `X-Real-IP` у домашніх мережах власника — `visitors.dir/home_networks.txt`, поза git; сама адреса не
пишеться), кількість повідомлень,
переглянуті `символ:TF` (до `max_views_per_visit`, решта рахується). **IP не пишеться.** Каталог створює ops з власником
процесу ws; сервер каталог не створює — нема каталогу = журнал вимкнено з WARNING `VISITORS_JOURNAL_OFF` на старті.
Збій запису — WARNING `VISITORS_JOURNAL_WRITE_FAIL`, графік працює далі. Зберігання — 12 місяців, старші місячні файли
видаляє зведення (S2).

### 3.3 Людина чи бот
Людина — UA не бот і (тривалість ≥ `human_min_session_s` (30) або ≥ 2 переглянутих `символ:TF`). Одне перемикання
може бути автоматичним: UI сам відновлює останню пару, якщо вона не типова (`App.svelte`, `loadLastPair`), тому «хоч одна
дія» людиною не робить. Решта — «схоже на бота»; бот без cookie-сховища щоразу отримує новий ключ і не «повертається».
Службові підключення (`internal`) — ні люди, ні боти: зведення їх не рахує (29.09 один прогін зонда рівнів за 90 с дав
75 таких сесій, і вони роздули б рядок ботів).
Свої — ключ з міткою `own` у `labels.json` або хоч однією сесією з домашньої мережі (`home_net`; рішення власника 03.10 —
автоматично): не рахуються ні людьми, ні ботами, видні рядком «Свої: візитів N (#ключ мітка|дім …)», щоб сторонній
з того самого провайдера не зник непомітно. Двоє різних людей з перетином візитів у часі позначаються «одночасно з #…»
(один на двох пристроях або дивились разом).

### 3.4 Боти й атаки — без спаму
Nginx пише запити сканерів (`wp-login`, `.env`, `.php`, …) у компактний окремий лог замість `access_log off`; зведення
раз на добу рахує категорії (краулери, сканування, відсічені лімітом 429) і топ-джерела (маска мережі /24, країна).
Миттєве повідомлення — лише інцидент (наплив > поріг протягом 5 хв або сплеск 5xx), не частіше ніж раз на годину.

### 3.5 Щоденне зведення — у ранковому звіті системного бота
Одне повідомлення на добу: люди (нові / повторні), список відвідувачів дня (№, країна, пристрій, з нами з, візитів,
тривалість), боти й атаки одним рядком. Доставляє ранковий звіт системного бота «Monitor» (ADR-0106 §3.5, 09:00 за
Прагою): watchdog запускає `tools.visitors.report` від власника журналу і вставляє текст. Окремого cron і відправника
немає; секрет бота — лише `/etc/aione-alerts/env` (не бот Арчі — одна особистість на бота).

### 3.6 Слайси
| # | Слайс |
|---|---|
| S1 | Ключ у cookie + журнал візитів на сервері (`runtime/visitors/journal.py`, хуки в `ws_handler`, config `visitors`) |
| S2 | Зведення (`tools/visitors/report.py`): люди/боти, нові/повторні, мітки, ретеншн 12 міс |
| S3 | Щоденне зведення — у ранковому звіті системного бота (ADR-0106 §3.5) |

## 4. Наслідки
- Власник бачить людей і повернення незалежно від IP і кешу; тривалість — точна (WS).
- Cookie з ключем — формально ідентифікатор; для відвідувачів з ЄС може знадобитися повідомлення/згода (вирішує
  власник до широкого запуску).
- Навантаження мізерне: один рядок на сесію.

## 5. Rollback
`visitors.enabled = false` + рестарт ws (cookie не видається, журнал не пишеться; вже видані cookie браузери
надсилають далі, сервер їх ігнорує); cron зведення — прибрати; nginx — повернути `access_log off`.
